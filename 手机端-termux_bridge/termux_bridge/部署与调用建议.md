# 手机端桥部署与 AI 侧调用优化建议

## 部署（Termux 内执行）
```bash
# 1. 杀掉旧桥（v2/v3 全部）
pkill -f bridge
rm -f /sdcard/Download/朱峰智能体/mailbox/bridge.lock

# 2. 安装 v4（PC 端把 手机端/termux_bridge/bridge_v4.sh 推到手机后）
install -m 755 /sdcard/Download/朱峰智能体/termux_bridge/bridge_v4.sh \
  /data/data/com.termux/files/usr/bin/bridge_v4
nohup bridge_v4 >/dev/null 2>&1 &

# 3. 开机自愈（Termux:Boot）
echo 'bridge_v4 &' >> ~/.bashrc
# 或 crontab 里每分钟拉起（脚本自带单实例锁，重复拉起无害）
```

## AI 侧调用纪律（为什么 term_run 全是 [无输出]）
1. **不要跑 sleep 长命令**：term_run 10000ms 超时，`sleep 10; ls` 必超时丢输出。轮询回执应多次短调用或直接 read_file。
2. **下发命令后立即返回**，等 30s+ 再 read_file `cmd_out/<name>.out`，别 13 秒后就去读。
3. **判存活只看心跳新鲜度**：heartbeat.txt 时间戳与当前差 <60s 即存活，不要依赖 pgrep（pgrep 在无输出时无法区分）。
4. **命令自带输出**：把想看的结果 echo 进 .cmd 脚本（如 check_dl.cmd 的写法就正确），AI 只读 .out。

## v4 相比 v3 的改进
- 单实例锁：杀掉重复启动问题（v2/v3 混跑、"No such file"）
- 原子改名消费：`.cmd → .running`，杜绝 selftest 执行 4 次的重复消费
- 命令级 120s 超时：死命令不堵通道
- .running 中间态：AI 可区分"没轮到"和"正在执行"
